# Decisions log

Settled, implemented decisions that are worth recording but not worth a full ADR. Each line is the decision as it stands today; the fuller reasoning (and any rejected alternatives) lives in git history under the original ADR file noted in parentheses. This is also the go-forward home for ordinary settled decisions — reserve a numbered ADR in `docs/adr/` for calls that constrain not-yet-built work or would need a deliberate revision to reverse.

- **Meals are day-granular, one per slot per actor.** `Meal` is keyed by `date` + `mealType` + `actor` (composite `MealId` `"${date}:${mealType}:${actor}"`), so a `(date, mealType)` pair holds up to one meal per actor; there are no user-facing meal times, and `createdAt` / `updatedAt` are system-stamped for audit. Breastmilk allergen transit is too diffuse for hour precision, and the rest of the model is already day-keyed. The `actor` dimension is the dual-actor build (ADR-0027, parked with the protocol engine — see [parked features](parked-features.md)). _(was ADR-0003)_
- **In-memory port adapters were dropped.** The hand-written `InMemory*` fakes for `ScheduleRepository` / `QuestionnaireRepository` had no consumers and were removed; adapters are tested against `fake-indexeddb`. _(was ADR-0013)_
- **Meal logging is commit-gated with fixed-at-entry type.** The `/meal` flow builds a working meal in memory and persists it only on the `Uložit` commit; the meal type is chosen at entry and not mutable mid-edit (no move/switch pills); deleting a whole meal is an explicit destructive-confirm action. _(was ADR-0018)_
- **Food-source subgroup is a second presentation axis.** A family's foods can cluster under a curated `familySources` subgroup (e.g. Kravské / Ovčí / Kozí / Rostlinné, S lepkem / Bez lepku) above the allergen axis — applied only to families with ≥ 5 foods and an authored entry, unsourced foods falling into a trailing _Ostatní_. Source is presentation-only and never enters the trigger path; the former `bez alergenu` grouping was dropped because it read as a false safety claim. _(was ADR-0019)_
- **Unlogged meal-slot rows are tappable add-entry points.** In `MealCard`, an unlogged slot row is a link that opens `/meal` with that slot's meal type pre-selected — a deliberate exception to the otherwise FAB-only write path. _(was ADR-0020)_
- **oxlint stays out for now.** Evaluated as a fast pre-filter ahead of ESLint (#480); as of oxlint 1.74.0 it has no Svelte plugin, so it can't lint the ~45 `.svelte` files that make up a fifth of this repo's lintable surface, and `bun run lint` already completes in ~4s. Revisit once oxlint ships Svelte support.
- **The loggable-window guard exempts unchanged-date edits.** `DexieMealRepository.save()` / `DexieSkinObservationRepository.update()` now compare the payload's `date` against the already-stored row's `date` (via `checkLoggableWindow`'s optional `existingDate` param) and skip the window check when they match, so editing a row that's already outside the window (e.g. after a schedule regeneration) doesn't block on fields that never touched the date. Explicit date changes are still guarded either way. The `/meal` and `/skin` editors show a passive "outside the protocol window" hint on such rows. _(#440)_
- **The ladder engine exposes a pure trace seam, not a parallel re-derivation.** `decideLadderMove` and `explainLadderMove` both delegate to one internal `walkLadderPrecedence`; the explain surface (`LadderExplain` = `{ decision, snapshot, steps }`, with `LadderStateSnapshot` projecting five replay facts and `steps` a fixed 6-tuple in precedence order) is an additive, read-only exposure of behavior the precedence already runs, so trace and verdict cannot drift. `deriveLadderState`/`LadderReplayState` stay private; `tools/ladder-viz` reads the cadence/skin-stability signals off this seam instead of re-calling the gates. _(#528, design #521)_
- **Ladder-viz scenarios are YAML, Zod-validated on load, with strict dates.** `tools/ladder-viz/scenarios/*.yaml` (header `allergen`/`phase`/`stage`/`permanent?` + `days: [{date, events}]`, event kinds `meal`/`skin`/`eval`) parse into the shared `JourneyRun` event-stream type both the replay and (future) manual mode render. Dates must be strict, consecutive, ascending — a duplicate / out-of-order / skipped date is a loud load error, since time-triggered engine transitions only render when every calendar day is a real entry. The allergen is validated against the catalog at the load boundary; the ladder is resolved from that catalog entry. _(#532, format settled in #523)_
- **The ladder explain seam carries a per-event replay trace for the viz tool.** `LadderExplain` gained a `replay` field (`LadderReplay` = `{ initial, steps }`, one `LadderReplayStep` per replayed `deriveLadderState` event, each with the branch taken + before/after frame). Produced by instrumenting the real loop via an optional sink — no parallel replay, no logic in the viz tool (the domain classifies the branch; the adapter only labels it). Derived and non-load-bearing (ADR-0012): no decision path reads `replay`. `tools/ladder-viz` renders it as a "replay ledger" under the pipeline, with pipeline back-links into the event that set the ceiling / pending reaction. Guarded by a "last step after == snapshot" test; maintenance contract lives on the `LadderReplayStep` type. A follow-up (#550) may unify the `LadderPrecedence*` / `LadderReplay*` naming under a `...Trace` family. _(builds on #528, design #521)_
- **FeedingStage is a live master switch, not a hardcoded constant.** A dedicated `settings` Dexie singleton (`SettingsData.feedingStage`, `SettingsRepository` port + adapter + `settingsContext` reactive store) holds the stage, seeded at first run and changeable via a Settings segmented control (`settingsStore.setFeedingStage`, owned by `stores/settings.svelte.ts`). It gates the actor pills via `getEligibleActors` and, since the descaling (PRD #623), is also the app's _seeded_ signal. _(#567, parent spec #564; revised ADR-0023 §Feeding stage — ADR-0023 parked with the protocol engine, see [parked features](parked-features.md))_
- **Emptying a meal deletes it.** `MealEditor.finalize()` on an _existing_ meal with zero confirmed foods removes the persisted row and reports `'deleted'`; on a compose-new it stays a no-op. Removing every food and then saving or backing out is a legitimate delete path — equivalent to the explicit "Smazat jídlo", writing the same `meal-delete` discard buffer so the `Jídlo smazáno` toast + `Zpět` undo behave identically. The edit CTA stays enabled when emptied (an inline hint warns that saving deletes the meal); `swapActor`'s silent autosave deletes an emptied departing meal too. Reverses the earlier #586 rule that "an empty meal never persists / empty-save is a silent no-op routing to Smazat". _(#588)_
- **Copy a meal to another slot.** The `⋯` overflow on the meal editor exposes _Kopírovat jídlo_ (only when the source meal has ≥1 food) → a destination picker (reused `DayStrip` + `FabActionSheet` slot sheet). The copy is **same-actor** (no actor picker; the destination is resolved actor-scoped via `loadBySlot(destDate, destSlot, source.actor)`) and **eligibility is not re-checked** on the destination date. Since the descaling (PRD #623 §3e) every reachable picker cell is a legal destination — the strip spans `earliest logged … today`, so no cell is future or out of window, and the "Kopírovat sem" button is always enabled. The merge is **additive, dedup-by-`foodId`, destination-wins** (a collision keeps the destination item, differing portion/prep does not override), the **source note never travels**, timestamps mirror ADR-0018, and a copy that would add nothing is a **no-op**. The write is **silent-merge with undo** (a `meal-copy` discard descriptor reverses just the added items / created row, invalidated by any manual edit of the destination). No new ADR — the merge lives in the pure `copyMealInto` assembler and the flow reuses existing components. _(spec #599)_
- **Restartovat is a true factory reset, behind a confirm.** `resetDatabase()` (`src/lib/db/reset-database.ts`) clears **every** table via `db.tables`, not a hand-written list. The predecessor (`settingsStore.reset()`) named four tables — three of them empty after the descaling — and spared the five holding the mother's meals, skin observations and photos, while the Czech copy promised to erase all saved data. The wipe is now honest, the copy names the photos, and a `ConfirmSheet` guards it: the action is irreversible and no backup mechanism exists, so the device holds the only copy. A whole-database wipe belongs to no domain, so it sits beside `atopic-db.ts` and outside per-domain adapter ownership. _(review of PR #638)_
- **One adapter instance per domain, owned by that domain's session store.** `stores/meal-session.ts` exports `mealRepository`; `stores/skin-observation-session.ts` exports `skinObservationRepository`. Four sites previously hand-rolled `new DexieMealRepository(db)`, leaving no single seam for the storage swap the architecture exists to enable. Cross-domain readers (`stores/earliest-logged.ts`) import the owning stores' instances rather than constructing their own. Module-scope singletons, not a DI container: adapters are tested against `fake-indexeddb`, so constructor injection would be ceremony with no payoff. _(review of PR #638)_
- **The day strip reaches back to the earliest logged day and a fixed week into the future, with no hard limit.** `computeDayStrip` spans `min(today − 7d, earliestLogged, selectedDate) … max(today + 7d, selectedDate)`. A ±7-day window around today is always present as a floor; logged data only ever extends the _past_ edge outward. The future edge is fixed at today + 7d — future-dated entries never push it further (so no `latestLogged` boundary is needed). Fresh install → a symmetric 15-cell window. Future days are ordinary, fully-loggable days — `resolveDay` no longer redirects a future param to today, and direct URL nav to a date outside the span still clamps the range outward to render it. No hard cap on past span (single-user PWA; contiguous render, no virtualization). No ADR — no not-yet-built work is constrained. _(#654)_
- **Custom food and harvest candidate are removed; the catalog is the whole set of loggable foods.** The `➕ Vlastní` tile, all free-text food entry, the `Dříve zadané` re-log list and the `harvest_candidates` read/write path are gone; `custom` leaves `FAMILIES` so `FamilyId` narrows by derivation, `FoodId` collapses to catalog ids, and `fromMealItems` throws on a non-catalog id rather than inventing a family for it. Foods outside the catalog can no longer be logged — an accepted, explicit loss of capability; a genuine gap is fixed by adding the food. Dexie **v12 deletes only the meals carrying an `other:` item** (custom-only or mixed, dropped whole rather than stripped), departing from the v7/v8/v10 whole-table wipe precedent because catalog-only meal history is still representable and worth keeping. `harvest_candidates` joins the dormant tables — declaration kept, `status` index dropped, rows survive unread. `normalizeKey` was rehomed to `domain/normalize-key.ts` and then deleted outright as dead code — no live caller ever appeared. `DEFAULT_PREPARATIONS` is deleted, so `preparationsForFood` returns `[]` for a miss (ADR-0028 amended, not contradicted). Both features are indexed in [parked features](parked-features.md) with revive notes. No ADR: this removes capability rather than constraining unbuilt work, and ADR-0017 was already dissolved. _(#662)_
- **Three unreachable components are deleted; `InfoBanner` is kept despite having no importer.** `error-alert.svelte`, `form-input.svelte` and `icons/CameraIcon.svelte` lost their call sites in the descaling (PRD #623) rather than never having been used; none appears in `docs/parked-features.md`, so they're recoverable from git history like any deleted file, not the `parked` revival index. `form-input`'s iOS Safari `input[type="date"]` width fix moved into the `.input-base` form atom in `app.css` so a future date input inherits it automatically. `InfoBanner` is spared because it's the sole renderer of the `[data-state]` Banner scale `DESIGN.md` documents — deleting it would orphan a documented design token. The five stale `docs/design/components-showcase.html` sections for parked protocol-engine components (`AllergenChip`, `PhaseBadge`, `ProgressBar`, `QuestionnaireSummaryRow`, `AllergenDrillIn`) are removed along with the now-orphaned `ErrorAlert`/`FormInput` sections, and a new showcase-sync test (`src/lib/test/showcase-sync.test.ts`) fails the suite if a `sync with:` path ever points at a file that no longer exists. _(#661)_
- **`CONTEXT.md` invariants carry stable `INV-<n>` ids.** The `## Invariants` list was an unnumbered 13-bullet list, citable only by file-order ordinal — which silently retargets every citation the moment a bullet is inserted. The 13 are now `INV-1..13` **in their existing file order**, so the `INV-n` citations already written into `docs/spec/meal-editor-state-machine.md` (#674) stay correct and needed no reconciliation. Ids are permanent identity, not position: assigned once, never reused, never renumbered; a new invariant appends the next unused number and need not be last in the list. Each carries an `<a id="inv-n">` anchor so it is linkable as `CONTEXT.md#inv-4` from repos that do not share this tree — the point, since the iOS spec lives in `eczema-ios` (#673) and references `CONTEXT.md` by pointer. The Actor invariant, which sat homeless in the glossary prose at `CONTEXT.md:327`, is promoted into the list as **INV-14**; the prose now cross-links it. Deliberately **not** numbered: the ~15 invariant-shaped rules stated in glossary prose (the `MealEditor` trio, the Copy Meal merge and flow rules, `SkinObservation` identity, the catalog **Principles**) — they are scoped explanations of their own entry, they would triple the series for no citation demand, and numbering them would invite drift between two parallel id spaces; cite those by glossary heading instead. Guarded by `src/lib/test/invariant-ids.test.ts` (four assertions: every bullet numbered, each id assigned once, no already-assigned id renumbered — checked against an `ASSIGNED` id→gist map — and every id has its anchor), mirroring the showcase-drift test seam from #661. _(#689, wayfinder map #672)_
- **ADR-0001 and ADR-0029 are scoped to this PWA, not superseded; ADR-0028 carries across untouched; and this repo must never be archived.** The iOS transition contradicts both in spirit — CloudKit sync against ADR-0001's single-device premise, and available-and-cheap field encryption (`@Attribute(.allowsCloudEncryption)`, #693) against ADR-0029's "no crypto" — but neither ADR became *wrong* about its own subject: this app still runs on one phone and still encrypts nothing. So each gains a `**Scope:**` line naming the PWA as its subject and pointing at the map, and keeps `Status: Accepted` with every existing sentence intact. Deliberately **not** the `**Amends:**` / `**Amended by:**` machinery: that convention is for a later decision *changing* an earlier one, and a second product making a different call is not that — using it would tell a future reader the PWA's own architecture was revised. No new ADR here either, and none yet in `eczema-ios`: the replacement decisions' content is still open on #705 (mandatory vs elective sync) and #714 (the per-field encryption list), so an ADR written now would restate tickets and create the cross-repo duplicate #696 exists to avoid — `eczema-ios` grows its own series when it has a decision that outlives a ticket (→ #719). **ADR-0028 (food-level preparations) is the odd sibling and stops being listed beside the other two**: it is a domain rule untouched by the platform change, so it ports intact and is cited by URL from the catalog spec section — and it stays *unpromoted* to an `INV-n`, being a food attribute rather than a domain invariant. **Freeze means no further code commits, never GitHub-archive**: archiving makes issues read-only ("To make changes in an archived repository, you must unarchive the repository first"), and the wayfinder map lives here as an issue precisely because transfers drop its dependency wiring — archiving would freeze the map itself, closing no ticket and recording no decision. `AGENTS.md` now states that in place, and its stale `src/lib/data/categories.ts` pointer is corrected to the bundled catalog. _(#688, wayfinder map #672)_
