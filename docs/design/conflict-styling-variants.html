▸ Decision summary

Trade-off: for
Trade-off: against
Variant A
White inset panel
Chips readable with no new component work. Red tile header zone reads clearly as danger.
Tile is visually "split" — two zones with different backgrounds. Slightly taller tile.
Variant B
Chips adapt to red
Most consistent — entire tile speaks one language. Active chip inversion (white/red) is distinctive.
Requires a variant="danger" prop on Chip. More implementation work.
Variant C
White bg, red border only
Zero contrast issue. Standard chips unchanged. Easiest to implement — just swap bg from red to white.
Editing state looks similar to idle-danger (both use pale red tint → white bg). Confirmed-red is loudest state — editing may feel understated.

Recommendation: Variant C for the fastest correct fix — swap the editing background from rgba(danger/0.05) to white, keep the 2px red border + red text + warning line. No new component work required. If the editing state needs to feel more alarming (user research feedback), upgrade to Variant A (white inset). Variant B is the most coherent but adds Chip API surface area.
