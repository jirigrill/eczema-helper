▸ MealCard — date, meals: Meal[], eliminatedToday: string[]

Single white card with internal dividers, eyebrow "Dnešní jídla". Always renders all four meal slots in order (Snídaně · Oběd · Svačina · Večeře). Three row states: (1) unlogged — muted icon (no circle), muted label, "+" on right, tappable → /meal?type=<slot>&date=<date>&returnTo=/day/<date>. (2) clean logged — primary icon in plain white circle, bold meal-type label, food names joined by " · " (no portion, no prep), chevron. (3) conflict logged — danger/15-tinted circle + danger icon, one "⚠ <Czech allergen name>" pill per distinct eliminated allergen the meal triggers, each triggering food in text-danger red, chevron. Conflict set = food's allergensForFood ∩ eliminatedToday.

▸ FamilyGrid — onSelect: (familyId) => void, activeFamilyIds?: FamilyId[]

Flat 4-column grid of family tiles. One tile per FAMILIES entry (14 total — 13 clinical + Vlastní). Two states: neutral (plain white) and active (white tile + small primary dot top-right — the family has a selection). The onboarding questionnaire passes activeFamilyIds to dot families with a chosen allergen; the meal grid leaves it empty, so its tiles are always plain — there the active/eliminated state is shown only on the food inside the drill-in (see FamilyDrillIn / FoodTile danger state), never on the family tile. There is no eliminated badge or danger tint on the grid anymore.

neutral (default)

activeFamilyIds=['fruit'] (white tile + primary dot)

▸ FamilyDrillIn — familyId: FamilyId, foods: WorkingFood[], eliminatedAllergenIds?: string[], customFoods?: {foodId, name}[], onFoodTap: (foodId, name) => void, onAmountChange: (foodId, amount) => void, onPreparationChange: (foodId, prep) => void, onCancelEdit?: () => void

Drill-in view for a single family. Foods rendered as FoodTile rows. When the family has ≥ 5 foods AND an authored entry in familySources (e.g. Mléko, Obiloviny — see ADR-0019), the foods are clustered under source-subgroup headers (Kravské / Ovčí / Kozí / Rostlinné, S lepkem / Bez lepku) in authored order, with any unsourced foods falling into a trailing Ostatní section. Otherwise the family renders flat (no headers). Each food reflects its WorkingMeal state: idle, editing (FoodEditor expanded beneath), confirmed (bordeaux fill), locked (dimmed). Per-food danger styling (red + Vyloučeno) is preserved in both grouped and flat modes when any of the food's allergenIds is in eliminatedAllergenIds. The Vlastní family shows previously-typed custom foods via customFoods, or an empty hint. The back arrow and family name live in the page's PageHeader, not here.

▸ FoodTile — name: string, state: 'idle' | 'editing' | 'confirmed' | 'locked', eliminatedStatus?: 'danger', lockedPrior?: 'idle' | 'confirmed', summary?: string, variant?: 'tile' | 'list', onclick?: () => void, onRemove?: () => void, editor?: Snippet

Per-food tile rendered in FamilyDrillIn (drill-in) and on the working-meal list. The `variant` prop adapts the confirmed fill to context: `tile` (default, drill-in) keeps the bordeaux fill so confirmed foods stand out from idle siblings; `list` (working-list) renders non-eliminated confirmed/locked-confirmed foods plain (white + dark text) since every food shown is already added — the porce summary + remove × already mark it. Eliminated (danger) foods keep the red treatment in both variants. Visual states reflect the working-meal state machine: idle (neutral, tappable), editing (primary border + expanded FoodEditor beneath), confirmed (bordeaux fill in `tile`, plain white in `list`, tap deselects), locked (dimmed, no interaction). lockedPrior branches the locked rendering: locked + prior='confirmed' keeps the confirmed fill at reduced emphasis (data-state='locked-confirmed' or 'locked-danger-confirmed') so the user can still see "this food is in the meal" while editing a sibling; locked + prior='idle' (or omitted) renders the grey outline. eliminatedStatus='danger' overrides state styling: idle→red tint + "Vyloučeno" suffix; editing→red border + "⚠️ Vyloučeno dnes" warning above editor; confirmed→filled red (data-state='danger-confirmed'). Optional `summary` slot renders a porce/příprava meta line on confirmed/locked-confirmed rows; optional `onRemove` renders a × action used by the working-list view. data-state values: 'confirmed', 'danger', 'danger-confirmed', 'locked', 'locked-confirmed', 'locked-danger-confirmed', or unset (idle/editing without conflict).

▸ FoodEditor — amount: PortionKind, preparation?: PreparationMethod, form: FoodForm, onAmountChange: (a: PortionKind) => void, onPreparationChange: (p: PreparationMethod | undefined) => void

Množství / Příprava picker that expands beneath a FoodTile in editing state. Uses Chip for each option. Active chip is filled (bordeaux). Tapping the active preparation chip deselects it (toggles to undefined). Clicking amount/preparation chips calls stopPropagation to avoid triggering FoodTile's onclick. The food's `form` (catalog metadata) gates which preparation chips render: `none` hides the Příprava row; `liquid` shows Syrové · Vařené · Pečené; `cookable` shows all five (Syrové · Vařené · Dušené · Pečené · Smažené); `raw-only` shows only Syrové.

▸ AllergenDrillIn — familyId: FamilyId, selected?: string[] (bindable), variant?: 'primary' | 'danger', onBack: () => void

Questionnaire allergen selector — one level shallower than FamilyDrillIn. Shows allergen chips for the given family. Chips toggle allergen ids into/out of selected[]. Used in steps 3 and 4 of onboarding. Single-allergen families are never passed here — collapse is handled by the parent page.
