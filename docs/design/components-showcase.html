▸ MealCard — date, meals: Meal[], eligibleActors: Actor[]

Single white card with internal dividers, eyebrow "Dnešní jídla". Always renders all four meal slots in order (Snídaně · Oběd · Svačina · Večeře). Single-actor stage (eligibleActors has one actor — breastfed→mother, solids→baby): each slot collapses to today's single row. Two single-row states: (1) unlogged — muted meal-type icon (no circle), muted label, "+" in the right rail, tappable → /meal?type=<slot>&date=<date>&returnTo=/day/<date>. (2) logged — primary icon in plain white circle, bold meal-type label, food names joined by " · " (no portion, no prep), "›". Dual-actor stage (mixed → [mother, baby]): each slot shows a shared meal-type header, then a stacked per-actor row for each eligible actor — marked by a fixed-width round actor icon (woman head-and-shoulders bust = mother, baby head with a curl = child; borderless traced silhouettes recolored via currentColor). Meal and actor icons share one iconMarker snippet, so the actor icon's paint tracks that row's meal state exactly like the single-row meal icon: empty → muted grey, logged → primary. Each row also shows plain wrapping foods and an indicator ("›" logged / "+" empty) in one fixed-width right rail so empty and logged rows align. When both actors are filled the per-row chevrons collapse to a single "›" centered across the two rows. When both actors are empty the whole section collapses to a single "+". The day view is logging-only — no allergen conflict detection or warning pills (PRD #623).

▸ FamilyGrid — onSelect: (familyId) => void, activeFamilyIds?: FamilyId[]

Flat 4-column grid of family tiles. One tile per FAMILIES entry (13 clinical families — the Vlastní tile went with custom-food entry, issue #662). Two states: neutral (plain white) and active (white tile + small primary dot top-right — the family has a selection). The onboarding questionnaire passes activeFamilyIds to dot families with a chosen allergen; the meal grid leaves it empty, so its tiles are always plain — there the active/eliminated state is shown only on the food inside the drill-in (see FamilyDrillIn / FoodTile danger state), never on the family tile. There is no eliminated badge or danger tint on the grid anymore.

neutral (default)

activeFamilyIds=['fruit'] (white tile + primary dot)

▸ FamilyDrillIn — familyId: FamilyId, foods: WorkingFood[], onFoodTap: (foodId, name) => void, onAmountChange: (foodId, amount) => void, onPreparationChange: (foodId, prep) => void, onCancelEdit?: () => void

Drill-in view for a single family. Foods rendered as FoodTile rows. When the family has ≥ 5 foods AND an authored entry in familySources (e.g. Mléko, Obiloviny), the foods are clustered under source-subgroup headers (Kravské / Ovčí / Kozí / Rostlinné, S lepkem / Bez lepku) in authored order, with any unsourced foods falling into a trailing Ostatní section. Otherwise the family renders flat (no headers). Each food reflects its WorkingMeal state: idle, editing (FoodEditor expanded beneath), confirmed (bordeaux fill), locked (dimmed). Catalog foods only — there is no free-text entry path (issue #662), so every family renders at least one food and there is no empty state. The back arrow and family name live in the page's PageHeader, not here.

▸ FoodTile — name: string, state: 'idle' | 'editing' | 'confirmed' | 'locked', lockedPrior?: 'idle' | 'confirmed', summary?: string, variant?: 'tile' | 'list', onclick?: () => void, onRemove?: () => void, editor?: Snippet

Per-food tile rendered in FamilyDrillIn (drill-in) and on the working-meal list. The `variant` prop adapts the confirmed fill to context: `tile` (default, drill-in) keeps the bordeaux fill so confirmed foods stand out from idle siblings; `list` (working-list) renders confirmed/locked-confirmed foods plain (white + dark text) since every food shown is already added — the porce summary + remove × already mark it. Visual states reflect the working-meal state machine: idle (neutral, tappable), editing (primary border + expanded FoodEditor beneath), confirmed (bordeaux fill in `tile`, plain white in `list`, tap deselects), locked (dimmed, no interaction). lockedPrior branches the locked rendering: locked + prior='confirmed' keeps the confirmed fill at reduced emphasis (data-state='locked-confirmed') so the user can still see "this food is in the meal" while editing a sibling; locked + prior='idle' (or omitted) renders the grey outline. Optional `summary` slot renders a porce/příprava meta line on confirmed/locked-confirmed rows; optional `onRemove` renders a × action used by the working-list view. data-state values: 'confirmed', 'locked', 'locked-confirmed', or unset (idle/editing).

▸ FoodEditor — amount: PortionKind, preparation?: PreparationMethod, preparations: readonly PreparationMethod[], onAmountChange: (a: PortionKind) => void, onPreparationChange: (p: PreparationMethod | undefined) => void

Množství / Příprava picker that expands beneath a FoodTile in editing state. Uses Chip for each option. Active chip is filled (bordeaux). Tapping the active preparation chip deselects it (toggles to undefined). Clicking amount/preparation chips calls stopPropagation to avoid triggering FoodTile's onclick. The food's own `preparations` list (catalog metadata, ADR-0028) is rendered chip-for-chip: an empty list hides the Příprava row; a liquid offers Syrové · Vařené · Pečené; a fry-able solid offers Syrové · Vařené · Pečené · Smažené; specialty foods add Sušené / Uzené / Naložené; a raw-only food offers only Syrové.

▸ AllergenDrillIn — familyId: FamilyId, selected?: string[] (bindable), variant?: 'primary' | 'danger', onBack: () => void

Questionnaire allergen selector — one level shallower than FamilyDrillIn. Shows allergen chips for the given family. Chips toggle allergen ids into/out of selected[]. Used in steps 3 and 4 of onboarding. Single-allergen families are never passed here — collapse is handled by the parent page.
